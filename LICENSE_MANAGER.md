# Менеджер лицензий — Семейный бюджет

Локальный инструмент владельца для выпуска offline-лицензий Version 8.2.

## Как выдать лицензию пользователю

1. Попросите пользователя открыть **Ещё → Активация и промокоды** и нажать **Копировать ID**.
2. Дважды откройте `LICENSE_MANAGER.cmd` (или выполните `npm run license-manager`).
3. Вставьте **ID установки пользователя** в обязательное поле.
4. При необходимости добавьте локальную заметку (необязательно).
5. Нажмите **Создать лицензию**.
6. Нажмите **Копировать код** и отправьте код пользователю.
7. Пользователь вставляет код в приложении: **Ещё → Активация и промокоды**.

Лицензия FULL_APP привязана к указанному ID установки и не активируется на другой установке.

## Важно

- Signing key хранится только локально в `.local-secrets/license-signing-key.json`.
- **Никогда не отправляйте** `.local-secrets/license-signing-key.json`.
- Не публикуйте этот файл и не включайте его в GitHub.
- Сделайте защищённую резервную копию ключа на своём компьютере.
- Поле «заметка» хранится только локально и не входит в код активации.
- Менеджер не требует ФИО, email, телефон или адрес получателя.
- Обязательный технический параметр: `installationId`.

## Если ключ потерян

- Ранее выданные лицензии K1 продолжают проверяться публичным ключом в приложении.
- Новые лицензии K1 выпустить будет невозможно, пока не восстановлен тот же private key.
- В будущем можно добавить ключ K2, не удаляя public key K1.

## Безопасность

- Сервер слушает только `127.0.0.1`.
- Private key не отдаётся через HTTP.
- User license Version 8.2 привязана к installation ID (не hardware fingerprint).
- Полная очистка site data браузера создаёт новый installation ID и может потребовать перевыпуска user license.
- Owner activation остаётся административным и не привязан к installation ID.
